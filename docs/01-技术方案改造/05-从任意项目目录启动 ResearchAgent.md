## 一、核心目标与命令接口规范

完成改造后，用户只需安装并配置一次全局凭据，在任意终端进入目标项目目录即可直接启动 `researchagent`：

| **用户输入**                             | **预期行为**                                                 | **退出码**                    |
| ---------------------------------------- | ------------------------------------------------------------ | ----------------------------- |
| `researchagent`                          | 以当前目录为工作区，进入交互式对话                           | 正常退出 `0`                  |
| `researchagent "梳理这个项目的目录结构"` | 初始化交互会话并自动发送首条任务；完成后留在同一会话等待追问 | 正常退出 `0`                  |
| `researchagent -p "检查 src 目录"`       | 单次执行模式（等价 `--print`），执行完直接退出               | 成功 `0` / 失败非 `0`         |
| `researchagent -c`                       | 继续当前目录、当前模型协议下最近更新的历史会话（等价 `--continue`） | 正常 `0` / 无会话或失败非 `0` |
| `researchagent -r`                       | 列出当前目录、当前模型协议下的历史会话，终端编号选择后恢复   | 正常或取消 `0` / 异常非 `0`   |
| `researchagent --resume <ID>`            | 保留现有显式恢复指定会话快照的行为                           | 正常 `0` / 找不到非 `0`       |
| `python -m agents.main "任务"`           | **向后兼容**：保持原有“执行一次后退出”的行为，避免破坏已有脚本 | 成功 `0` / 失败非 `0`         |

## 二、详细技术改造设计

### 1. 打包入口与跨项目配置发现

+ **全局命令注册（`pyproject.toml`）**：

  + 补充标准打包配置，注册 `[project.scripts]`：

    Ini, TOML

    ```
    [project.scripts]
    researchagent = "agents.main:cli_main"
    ```

  + 支持 `pip install -e .`（开发态）与 `pip install .`，确保离开源码目录且不设置 `PYTHONPATH` 时可直接调用。

+ **配置加载优先级（从高到低）**：

  1. **当前进程环境变量**（最高优先级，方便临时覆盖或 CI/脚本注入）
  2. **当前工作目录 `.env`**（`<cwd>/.env`，支持项目级自定义模型/Key）
  3. **全局配置文件**（`~/.researchagent/.env`，一次配置，跨项目生效）

  + *实现注意*：使用 `dotenv` 加载时，先加载 `<cwd>/.env`（`override=False`），再加载 `~/.researchagent/.env`（`override=False`），即可自然满足 `系统环境变量 > 项目 .env > 全局 .env` 的优先级。

+ **工作区显式传递（为后续桌面端留好边界）**：

  + 在 CLI 入口统一解析 `workspace_dir = Path.cwd().resolve()`，作为参数向下传递给会话管理、规则加载（`load_claude_md()` / `.research/rules/*.md`）与工具执行器，避免在新增代码中散落 `os.getcwd()`。

### 2. 交互首轮任务与单次执行分流（`agents/main.py`）

+ **统一内核，双入口路由**：
  + 抽离内部主函数（如 `_run_cli(argv=None, *, default_interactive: bool)`）：
    + `cli_main()` 调用 `_run_cli(default_interactive=True)`，供 `researchagent` 命令使用。
    + `if __name__ == "__main__":` 调用 `_run_cli(default_interactive=False)`，保持 `python -m agents.main "任务"` 的旧行为。
+ **位置参数与 `-p` 行为**：
  + 当传入 `-p` / `--print` 时：必须提供任务文本（若缺失则报错退出）；复用现有单次执行路径，捕获未处理异常并返回非 `0` 退出码。
  + 当 `default_interactive=True` 且有位置参数、未传 `-p` 时：
    1. 先完成交互模式所需的回调注册（工具审批回调、流式输出回调、会话初始化）。
    2. 自动将位置参数作为首轮用户输入送入同一个对话循环。
    3. 首轮工具审批与模型回复结束后，**不退出**，直接进入下一轮 `input()` 等待用户追问，且第二轮上下文完整保留第一轮结果。
+ **共用执行主干**：交互首轮任务与 `-p` 必须共用同一套模型客户端、权限校验与工具循环，禁止复制两套 Agent Loop。

### 3. `-c` 续接与 `-r` 历史会话选择（`agents/main.py`、`agents/session.py`）

+ **统一筛选条件**：

  + `-c`、`-r` 与 `--resume` 必须复用 `agents/session.py` 中同一套过滤与排序函数：按 **当前 `workspace_dir` + 当前模型协议** 筛选，按 **最近更新时间倒序** 排列。

+ **参数互斥校验**：

  + `-c`、`-r`、`--resume <ID>` 三者互斥；同时传入任意两个时，直接提示参数冲突并以非 `0` 退出码退出。
  + 若 `-c` 或 `-r` 与 `-p "任务"` 组合使用，需明确支持（恢复该会话后执行单次任务并保存）或显式拒绝并报错，避免静默忽略参数。

+ **`-c`（续接最近会话）**：

  + 若当前目录与协议下无匹配会话：打印明确提示（如“当前目录与协议下未找到可恢复的历史会话”）并返回非 `0` 退出码，不静默新建空会话。
  + 若找到匹配会话：加载历史消息与状态，恢复后新产生的对话继续追加写入原会话文件。

+ **`-r`（终端交互选择列表）**：

  + 不引入重型 TUI 库，采用纯终端编号菜单，保证 Windows / WSL / Linux 跨终端稳定：

    Plaintext

    ```
    当前项目与协议下的历史会话（按最近更新排序）：
    [1] 2026-11-26 14:20 | sess_a1b2c3 | 梳理这个项目的目录结构
    [2] 2026-11-25 19:05 | sess_d4e5f6 | 修复 tool_call 孤立消息
    请输入编号恢复会话（输入 q 取消）：
    ```

  + 边界处理：

    + **空列表**：提示无历史会话并安全退出。
    + **取消选择**：输入 `q` / 空回车 / `Ctrl+C` 时优雅退出（退出码 `0`），不抛堆栈。
    + **非法输入**：非数字或越界编号时提示重新输入或安全退出。

## 四、验收与测试清单

### 1. 自动化单元测试（Mock 模型与终端输入）

+ **配置加载**：验证 `环境变量 > 项目 .env > 全局 ~/.researchagent/.env` 覆盖顺序。
+ **入口路由**：验证 `researchagent`、`researchagent "task"`、`researchagent -p "task"`、`python -m agents.main "task"` 的分支调用与退出码。
+ **会话恢复**：构造 **2 个项目目录 × 2 种模型协议** 的测试会话，验证 `-c` 与 `-r` 严格隔离、按更新时间倒序；验证空列表、`q`/`Ctrl+C` 取消、越界编号、参数冲突，以及恢复后继续写入原会话文件。

### 2. 端到端里程碑验收（手工跑通）

1. 在 `ResearchAgent` 仓库执行 `pip install -e .`，在 `~/.researchagent/.env` 配置凭据。
2. **新开终端**，`cd` 到一个**不包含 ResearchAgent 源码**的项目目录（内含 `CLAUDE.md` 或 `.research/rules/*.md`）。
3. 运行 `researchagent "读一下这个项目的规则"`，确认无需 `PYTHONPATH`、准确读取目标项目规则、获批的文件修改落在目标项目中，且回答后可直接追问第二轮。
4. 退出后在同目录分别测试 `researchagent -p "列出当前目录文件"`（执行完退出且退出码为 `0`）、`researchagent -c` 与 `researchagent -r`。
