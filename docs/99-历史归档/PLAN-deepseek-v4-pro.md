# DeepSeek V4 Pro 适配计划

日期：2026-10-12  
状态（2026-10-13 更新）：第二阶段核心真实流程及退出清理专项测试已通过；子 Agent、fork Skill、关闭思考回归及中断恢复仍待真实补测，完整验收尚未完成

## 目标与范围

先以关闭思考模式的最小改动验证 BearCode 的基本 Agent 流程，再逐步支持 DeepSeek V4 Pro 的思考模式和长期任务。

第一阶段使用 DeepSeek 官方 OpenAI 兼容接口：

```dotenv
APIKEY=由用户自行填写
API=https://api.deepseek.com
MODEL=deepseek-v4-pro
```

本计划不要求读取、展示或记录用户的 API Key。现有 conda 环境 `BearAgent` 已安装项目 Python 依赖。

## 实施前依据

以下为第一阶段实施前的历史状态，当前代码进展以第二阶段实施记录为准。

- 项目已有 `--thinking`，但模型判断和请求控制主要针对部分 Claude 模型。
- OpenAI 主请求没有明确发送 DeepSeek 思考开关，也没有收集和回传 `reasoning_content`。
- DeepSeek 默认开启思考；仅不传 `--thinking`，不能明确关闭服务端思考。
- 辅助请求也会调用模型，用于记忆检索、上下文压缩和 Skills 自进化。
- V4 Pro 未配置专用上下文容量，费用估算仍使用固定单价。

依据：[官方思考模式与工具调用文档](https://api-docs.deepseek.com/zh-cn/guides/thinking_mode/)、[官方模型与计费文档](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)。实施前应复核接口行为。

## 第一阶段：明确关闭思考，验证基本运行

### 改动

1. 在 `agents/agent.py` 中统一构造 DeepSeek 请求参数，只对本阶段指定的模型和官方 OpenAI 接口生效，其他模型保持原有行为。
2. 在 `_call_openai_stream()` 和 `_build_side_query()` 的 OpenAI 请求中明确传入：

   ```python
   extra_body={"thinking": {"type": "disabled"}}
   ```

3. 新增读取配置 `BEAR_DEEPSEEK_THINKING=disabled`；本阶段目标模型未配置时也默认关闭。校验配置值；若要求开启思考，包括传入 `--thinking`，明确提示本阶段尚未支持，不静默忽略。
4. 在 `.env.example` 和使用说明中记录配置方法。该变量由本阶段代码读取；实际 `.env` 由用户自行维护。

核心代码预计修改约 30～60 行，主要限定在 `agent.py`；测试与文档另计。`main.py` 已加载 `.env`，本阶段无需新增命令行参数。

- 用户配置密钥后，验证普通对话、连续两轮对话，以及“读取文件 → 搜索相关代码 → 回答”的连续工具调用，无消息格式或思考字段缺失报错。

## 第二阶段：长期支持 DeepSeek V4 Pro

本轮实施方案（2026-10-12，官方文档已复核）：

- 继续限定 `deepseek-v4-pro` 与官方 HTTPS Chat Completions 接口，Anthropic 兼容接口和第三方网关不在本次范围。
- 优先级：CLI / 显式构造参数 > 环境变量 > 本地默认。保留默认关闭；新增 `--no-thinking`、`--reasoning-effort low/high/max`、`--max-output-tokens`。辅助任务独立开关，默认关闭。
- 收集完整流式 `reasoning_content`，保留在每个对应 assistant 消息上，包括普通回答。仅将最终回答送入子 Agent 输出和 Skills 提取；界面显示思考状态，不把思考文本混入回答。
- 恢复旧历史时缺少思考字段则拒绝思考加工具请求，不伪造空思考；提供新会话、关闭思考恢复，或关闭模式先压缩再切换的路径。
- 压缩只保留新的 system 与结构化 user 摘要，删除整组原始历史，不能单独删除仍保留 assistant 的思考字段。流式中断时关闭流，不保存不完整的 assistant / tool_calls。
- 两种子 Agent 构造显式继承有效配置、输出预算及估算价格，避免 CLI 开关丢失；回传主请求与辅助请求用量。
- 官方模型上下文为 1048576，输出上限 393216。主请求默认非思考 16384，思考 low/high 65536、max 131072；允许 CLI 修改。压缩窗口扣除输出预算和额外余量。
- DeepSeek 截断、过滤、未完整结束或无效工具 JSON 不执行工具，也不保存该 assistant 消息。辅助截断明确失败，由现有压缩兜底保留信息。
- 按缓存命中/未命中分别累计 USD 估算，输出 token 已含思考不能重复计费；默认使用 2026-10-12 官方峰价保守估算，允许显式设 `BEAR_DEEPSEEK_PRICE_PERIOD=off_peak`。不猜测中国节假日或跨时段实际计费，不声称精确账单或严格限额。

可行性检查结论：现有 JSON 会话结构可以保留额外消息字段；两处子 Agent 入口与辅助工厂能够统一传递配置；压缩整组替换历史符合思考字段要求。主要风险为旧历史、截断、中断与用量漏计，已用离线模拟接口覆盖。本轮按约定不读取密钥或执行真实请求。

完整目标包括：

1. **思考模式**：支持明确开启、关闭和思考强度；规定 `.env` 与命令行参数的优先级。辅助任务默认关闭思考，允许独立配置，避免小输出预算被思考内容耗尽。
2. **消息协议**：拼接流式 `reasoning_content`，保存到对应 assistant 消息；携带工具时完整回传仍保留的历史思考字段，包括没有实际调用工具的轮次。
3. **会话与压缩**：验证保存、恢复、压缩和中断后的消息完整性；旧会话缺少思考字段时提供明确处理方式，不伪造字段。已有通用 JSON 存储优先复用，按实际需要修改。
4. **子 Agent**：主 Agent、普通子 Agent 和 fork Skill 使用一致的模型配置，并验证配置继承及用量统计。
5. **长上下文与输出**：补充官方模型容量和输出预算，检查压缩阈值；处理输出截断，避免把不完整的工具参数当作正常调用执行。
6. **用量与费用**：记录缓存命中等用量，统一 `agent.py` 的预算估算与 `ui.py` 的显示；明确计费币种和分时价格依据，仍以服务商账单为准。
7. **回归测试与文档**：覆盖思考开关、流式拼接、多轮工具调用、恢复、压缩、子 Agent，以及既有模型的请求行为。

核心代码初估约 150～300 行；加上测试和文档，整体约 300～600 行。具体范围在第二阶段审计时确认。

第二阶段的完成标准是思考开启与关闭均通过多轮工具任务，并验证会话恢复、主动压缩、子 Agent 和输出异常处理。Anthropic 兼容接口和其他 API 协议不属于本计划的必需范围，如有需求另行扩展。
