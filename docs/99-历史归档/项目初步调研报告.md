# ResearchAgent 项目初步调研报告

2026 年 11 月 21 日 · 基于当前工作区

## 项目定位

ResearchAgent 是当前目录名，README 使用 Bear Agent 和 BearCode。项目以 Python 实现一个可在本地运行的通用 Agent 框架。用户可以通过命令行提交一次性任务，也可以在交互会话中持续工作。模型负责推理并提出工具调用，运行时负责检查权限、执行工具、回传结果和保存会话。项目说明列出了从 MIT 许可上游复用的基础模块。[当时的项目说明](README.original.md) · [设计动机](../../为什么还要做ResearchAgent.md)

**初步判断**：现有代码适合研究两个具体问题：用户的纠正怎样影响下一次相似任务，以及长对话经过压缩后怎样继续执行。两者都有实现和评测入口。当前材料对实现机制交代得较清楚，对实际任务成功率提高了多少，还缺少可直接复核的本项目对照结果。

## 一次任务如何运行

| 环节 | 运行时做什么 | 主要源码 |
| --- | --- | --- |
| 接收任务 | CLI 解析模型、权限和会话参数，进入交互或一次性执行模式。 | [main.py](../../agents/main.py) |
| 准备上下文 | 主 Agent 在首次对话时按配置连接 MCP 服务，每轮检索相关 Skills；提示词与项目记忆为模型补充背景。 | [agent.py](../../agents/agent.py) · [prompt.py](../../agents/prompt.py) · [memory.py](../../agents/memory.py) |
| 调用与执行 | 运行时分别处理 OpenAI 兼容和 Anthropic 兼容消息，检查工具调用及权限，再将结果交回模型。工具涵盖本地文件、Shell、Skills、子 Agent 和 MCP 服务。 | [agent.py](../../agents/agent.py) · [tools.py](../../agents/tools.py) · [mcp_client.py](../../agents/mcp_client.py) |
| 保存与继续 | 主会话保存到本地，支持恢复。历史较长时可压缩为事件、工作和工具记忆；折叠记录可供回查。 | [session.py](../../agents/session.py) · [session_memory.py](../../agents/session_memory.py) |

例如，用户要求“今后的调研报告要给出可核查来源”时，系统可以把这条反馈与上一轮任务及回复合并分析。在配置和写权限允许时，系统创建或更新项目级或用户级 `SKILL.md`，记录来源和版本。后续同类任务可以检索到这条规则。项目长期记忆另按工作目录区分，用来保存项目背景、偏好等信息。[反馈提取](../../agents/online_skill_evolution.py) · [Skill 检索](../../agents/skills.py) · [版本与审计](../../agents/skill_evolution.py)

## 两条评测链路能回答什么

**Skills 评测能定位哪些要求经常被遗漏。** `/skill-eval` 从历史对话构造回放样本，按规则检查回复，针对失败项生成候选 Skill，再用候选重答。当前版本主要沿用历史回答，候选版本使用新生成的回答。例如，判断回答有没有列出来源，能检查格式遵从度；判断引用能否支撑结论，仍需要核查来源内容。若要估计任务成功率增益，需要让新旧版本在相同条件下完成同一批留出任务。[评测实现](../../agents/online_skill_eval.py) · [项目评测口径](../../项目评测.md)

**折叠评测能比较同一题在保留完整历史和压缩历史时的表现。** 入口会记录模型配置、样例哈希、逐题结果和配对有效性。当前副本缺少 README 命令指定的 `data/folding_eval_smoke.jsonl`，复现示例首先需要补齐案例。文档引用的 53.3%、20.2%、44.7% 均标明来自 DeepAgent 论文，BearCode 自身的成绩需从本项目运行结果计算。[评测入口](../../agents/eval_folding.py) · [折叠评测说明](../../wiki/折叠评测部分.md) · [当时的 README](README.original.md)

## 后续核验优先级

1. **先建立可复现的运行基线。** 在依赖齐全的独立环境运行全量离线测试，记录解释器、依赖版本、通过和跳过项。优先补回折叠样例及 MCP 迁移验收记录，使 README 的示例和结论均可追溯。
2. **再验证项目最有特色的能力。** 选一批没有参与 Skill 生成的代表任务，固定模型、工具和预算，在旧版与新版 Skill 下各运行一次。分别统计任务完成、规则遵守、成本和退步案例。折叠实验则单独报告有效配对数量、正确率和未进入统计的原因。
