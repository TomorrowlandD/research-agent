# 双协议模型接入

**结论（2026-11-22）。** 两个协议均已跑通“检索 Skill → 模型请求工具 → 执行并回写 → 继续回答”。主 Agent 在分流前检索 Skills；两条循环都支持 Memory 异步预取，并共用参数校验、权限和工具执行入口。预取完成后才会在循环中注入记忆。[对话入口](../../agents/agent.py#L513) · [工具分派](../../agents/agent.py#L1317)

| 协议 | 同一次工具调用如何往返 |
| --- | --- |
| OpenAI-compatible | 把工具定义转换为 `function.parameters`，按流式片段的索引拼接工具名和 JSON 参数。执行后以 `role=tool`、`tool_call_id` 回写。官方 DeepSeek V4 Pro 思考模式还需保留历史的 `reasoning_content`。[请求与拼接](../../agents/agent.py#L2084) · [历史校验](../../agents/agent.py#L312) |
| Anthropic-compatible | 单独传 `system`，按内容块索引组装 `tool_use`；等响应完整后再执行。在下一条 user 消息中，以 `tool_result.tool_use_id` 匹配原调用。[事件组装](../../agents/agent.py#L1774) · [结果回写](../../agents/agent.py#L1750) |

**运行验证。** WSL、Python 3.11，使用已安装的两个 SDK 和仅监听本机的模拟服务。在相同临时项目里，两边都把分片参数组装为一次真实的 `read_file` 调用；第二次模型请求含原调用 ID、读出的文件内容和已完成预取的 Memory，最终均返回预设回答。真实服务商端点尚未联调。[已有协议回归](../../tests/test_tool_arguments.py#L55)

**Web 接入评估：运行循环可复用，协议选择需显式化。** 离线复查确认，仅配置 `OPENAI_API_KEY` 时，CLI 解析器选 OpenAI，但传入 Agent 的地址为空，最终实例化 Anthropic 客户端。指定 `ANTHROPIC_BASE_URL` 时也要看 URL 路径：本地样例的 `/v1` 走 OpenAI，`/anthropic` 才走 Anthropic。Web 配置应分别保存协议与端点，并按实际客户端核对连接。[CLI 解析](../../agents/main.py#L106) · [参数传入](../../agents/main.py#L439) · [Agent 选择](../../agents/agent.py#L180)
