# Memory 长期记忆

**核心结论。** 记忆条目和索引按当前工作目录的哈希存放。存储函数可以保存偏好并重建索引；模型按系统提示使用通用文件工具首次创建记忆时，可能报告成功却写到工作目录。这会让下一个会话无法发现该条目。[存储与索引](../../agents/memory.py#L52) · [模型写入指引](../../agents/memory.py#L396) · [工具路径解析](../../agents/tools.py#L260)

- **索引与正文分开进入上下文。** 系统提示可携带当前项目的索引。主 Agent 在查询含空白、目录有条目且未达到会话预算时异步预取；辅助模型从候选摘要选最多五个文件。循环仅在轮首检查是否已就绪，已注入的路径在同一 Agent 中去重。没有空格的中文问句也会跳过这次自动预取。[筛选](../../agents/memory.py#L262) · [触发条件](../../agents/memory.py#L354) · [注入时点](../../agents/agent.py#L1874)

**离线验证。** WSL、Python 3.11.18，临时用户目录及两个项目。新条目的绝对目标路径尚不存在时，真实 `write_file` 在工作目录生成同名文件，目标目录和索引均无该条目。改用 `save_memory()` 后索引更新。固定召回选择，在新 Agent 的单次回答中未见正文，执行一次工具后的第二次模型请求收到了正文；切换项目目录后索引中没有该偏好。

**Web 接入。** 优先修正并回归模型实际使用的写入入口，再承诺跨会话记忆。工作目录哈希需要映射到用户和工作区；若产品要求首答采用既有偏好，还需明确首轮等待召回的策略。
