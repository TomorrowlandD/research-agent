# Skills

**核心结论。** Skills 有两条路径：当前任务先检索已有技能，再按需调用正文；上一轮的用户反馈则可触发后台维护，改变以后能检索到的技能。

- **发现与调用。** 用户级和项目级按名称合并，同名时用户级优先。检索按词项相关度评分，前几项以描述和适用条件注入当前请求。显式调用才展开正文和参数；inline 把指令交还当前循环，fork 让子 Agent 执行。[发现](../../agents/skills.py#L82) · [检索与注入](../../agents/skills.py#L257) · [调用](../../agents/agent.py#L1361)
- **反馈到写入。** 主 Agent 保留上一轮对话窗口，下一条输入补入反馈。Extractor 提取候选，Maintainer 提议新增、合并或丢弃，精确身份匹配会强制合并。后台写入只在 `acceptEdits` 或 `bypassPermissions` 放行。处理结果记入 provenance；“检索到”“被判相关”“被判使用”分别计数，后两项通常由辅助模型判定。[窗口与写入条件](../../agents/agent.py#L731) · [维护决策](../../agents/online_skill_evolution.py#L136) · [使用统计](../../agents/skill_evolution.py#L453)

**离线验证。** WSL、Python 3.11.18，临时用户目录与项目目录，模型回复及提取／维护判断固定。实测同名检索和显式调用均选用户版；连续对话在默认权限下记录拒写，在允许编辑时新增，同一候选再次出现后合并。新 Agent 在请求中收到该技能，使用判断写入统计。真实反馈的提取质量仍待评测。

**Web 接入。** 检索和演化流程可复用。技能发现缓存位于进程全局，待提取窗口和后台任务属于 Agent 实例；多用户服务需要绑定技能作用域，并区分反馈已收到、维护被拒和文件已写入。
