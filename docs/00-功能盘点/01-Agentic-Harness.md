# Agentic Harness

**核心结论。** 一次用户请求可以触发多次推理。主 Agent 读取完整模型响应，拿到工具请求后等待权限决定，再把执行结果或拒绝原因按调用 ID 配回消息历史。拒绝一次工具调用后，模型仍有机会给出最终回答。[对话入口](../../agents/agent.py#L513) · [OpenAI 循环](../../agents/agent.py#L1933) · [Anthropic 循环](../../agents/agent.py#L1671)

- **何时执行与停止。** 运行时校验工具调用标识和参数，再按权限分派。无工具请求时结束本轮；工具轮数或费用超限时回写跳过原因并停止。工具轮结束后检查是否需要压缩上下文。[预算检查](../../agents/agent.py#L907) · [工具分派](../../agents/agent.py#L1317) · [压缩检查](../../agents/agent.py#L1016)
- **何时保存。** 主会话在本轮收尾时写入协议消息、元数据和折叠记忆。`restore_session()` 可重建消息历史。审批等待中的协程只存在于进程内；自动保存吞掉写入异常，调用方收不到持久化失败信号。[收尾](../../agents/agent.py#L546) · [保存](../../agents/agent.py#L996) · [恢复](../../agents/agent.py#L928)

**运行验证 · 2026-11-22。** WSL Ubuntu、Python 3.11.18，使用模拟 OpenAI 流式响应和真实 `write_file`。通过 `Agent.chat()` 分别批准、拒绝创建临时文件：仅批准时生成文件，两次的下一次模型请求均带有对应调用 ID 的结果。首轮等待审批时磁盘上尚无会话快照；两次收尾后，新 Agent 均从磁盘快照还原了相同消息历史。[流式测试替身](../../tests/test_deepseek_thinking.py) · [会话读写](../../agents/session.py#L26)

**Web 接入评估。** 推理与工具循环可复用。需要可靠保存或重启续办的任务，应让上层能区分“回答已结束”“历史已落盘”和“审批仍待处理”。
