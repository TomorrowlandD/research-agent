# 用量、预算与调用追踪

**核心结论。** Agent 在内存中维护主调用和辅助调用的 token 计数，并据此估算费用。费用和轮数上限在工具执行前检查，触发本次工具请求的模型调用已经发生。普通会话快照保存工具调用 ID 和消息历史，但没有逐次模型调用的用量账本。[计数入口](../../agents/agent.py#L322) · [预算判断](../../agents/agent.py#L907) · [快照字段](../../agents/agent.py#L996)

| 问题 | 已确认的行为 |
| --- | --- |
| 哪些调用计入 | 主推理记入主计数。Memory 召回、Skills 提取／维护／使用判断、折叠摘要走辅助计数；折叠按模式发出一次或三次请求。子 Agent 和 fork Skill 正常返回时，用量归并到父 Agent。后台 Skills 可在 `run_once()` 返回后才记账。[辅助请求](../../agents/agent.py#L401) · [单轮差额与归并](../../agents/agent.py#L564) · [折叠请求](../../agents/agent.py#L1070) |
| 美元估值怎么算 | 官方 DeepSeek V4 Pro 适配按内置时段费率区分缓存命中、未命中和输出，推理 token 已包含在输出。其他模型统一按每百万输入／输出 token 3／15 美元估算。`/cost` 含主、辅助计数，普通兼容接口的轮末费用展示只用主计数。[费率实现](../../agents/deepseek.py#L71) · [轮末展示](../../agents/agent.py#L337) · [汇总估值](../../agents/agent.py#L888) |
| 何时拦截 | 含工具调用的模型响应使轮数加一，达到上限就跳过整批工具；纯文本回答不增加工具轮数。父任务下发剩余轮数，子任务已用轮数不累加回父任务。官方 DeepSeek 辅助请求另有调用前检查。Shell 和 MCP 各有超时，普通对话主循环未见整项任务截止时间。[协议检查点](../../agents/agent.py#L1680) · [OpenAI 检查点](../../agents/agent.py#L1939) · [子任务上限](../../agents/agent.py#L1544) · [Shell](../../agents/tools.py#L553) · [MCP](../../agents/mcp_client.py#L309) |

**离线对账 · 2026-11-22。** WSL、Python 3.11，固定 SDK 用量、真实读文件。一次父任务发出五次模型请求：父推理 250/25、子推理 140/14、Memory 召回 30/3（输入/输出），合计 **420/42 token，估算 0.001890 美元**。新 Agent 恢复同一快照后，用量、轮数与估值均为零。另测得 `--max-turns 1` 跳过首批工具，极低费用上限也跳过工具，两者均仍可发起下一次纯文本请求。后台 Skills 判断的 9/2 token 在本轮差额返回后才进入累计值；模拟 OpenAI 回复缺少 usage 时记为 0/0。仓库 DeepSeek 配置和计费相关两组回归共 30 项通过。[计费回归](../../tests/test_deepseek_thinking.py#L326) · [配置回归](../../tests/test_deepseek_config.py)

**Web 接入评估。** 实时用量展示可以复用现有计数器。按用户限额或任务对账还需要持久记录任务、父子调用、用途和实际返回的 usage，区分“用量缺失”与“零消耗”，并在发出请求前检查可用额度。真实服务商账单尚未核对。
