# 工作区与执行环境

**结论（2026-11-22，源码复查与 WSL 离线验证）。** CLI 启动时的当前目录决定相对路径的起点。两个 Agent 即使有不同的会话 ID，只要运行在同一目录，就能读到同一份任务产物。会话快照记录工作目录；从另一个目录恢复历史后，工具会使用新的当前目录。

| 核心行为 | 实现与边界 |
| --- | --- |
| 文件与产物 | `_resolve_tool_path()` 按进程当前目录解析相对路径，也接受已有的绝对路径；`_write_file()` 创建所需父目录并写入目标文件。普通产物随目录保留。Docker 镜像以 `/workspace` 启动 CLI，工作区的实际可见范围由进程权限和容器挂载决定。[文件工具](../../agents/tools.py#L260) · [容器入口](../../Dockerfile#L44) |
| Shell 与取消 | 每次 `run_shell` 同步启动一个子进程，继承当前目录与环境。命令内的 `cd` 仅作用于该次调用；默认超时 30 秒。Agent 取消的是异步任务，Shell 执行处未向它提供子进程句柄。用户取消后能否及时停止整个进程树仍待验证。[Shell 执行](../../agents/tools.py#L553) · [工具分派](../../agents/tools.py#L825) · [Agent 取消](../../agents/agent.py#L460) |
| 会话与运行时文件 | 完整会话写入 `~/.research/sessions/`，折叠记录写入当前项目的 `.research/sessions/`，触发大结果落盘时写入 `~/.research/tool-results/`。CLI 的 `--resume` 从用户会话目录取最近记录，恢复消息与折叠记忆；保存的 `metadata.cwd` 不会切换工具的工作目录。[存储](../../agents/session.py#L12) · [大结果落盘](../../agents/agent.py#L1281) · [CLI 恢复](../../agents/main.py#L449) · [恢复逻辑](../../agents/agent.py#L928) |

**运行验证。** WSL Ubuntu、Python 3.11.18，临时用户目录和两个临时项目，无模型或 MCP 调用。同一目录下，Agent A 用 Shell 生成文件，Agent B 用文件工具读到了内容；子进程读到了合成环境变量，下一条命令回到启动目录，100 ms 前台命令超时按预期返回。在项目 B 恢复项目 A 的会话后，读取同名相对路径得到 B 的内容。既有文件读取和检索测试另行运行，9/9 通过：`python -s -B -m unittest discover -s tests -p test_windows_tools.py -v`。

**Web 接入评估：需适配。** 可复用单次工具执行逻辑。任务启动和恢复时都应显式绑定所属工作区，并据此定位和授权访问产物。同一服务进程内切换全局当前目录会影响其他任务；工作区标识本身也不能限制 Shell 的文件访问范围。容器挂载隔离和取消后的进程回收尚待部署环境验证。
