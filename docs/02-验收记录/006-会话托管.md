# 006 后端基础设施改造 · Commit 3 会话托管

2026-11-27，在 WSL Ubuntu、Python 3.11.18 的 `researchAgent` 环境验收。模型响应使用本地模拟数据。会话、审批、文件工具、JSONL、WebSocket、Chromium 和 Playwright MCP 均通过各自的运行入口验证。

| 场景 | 结果 |
| --- | --- |
| 同进程双工作区 | 两个 Web 会话对同名相对路径发起写入，分别命中各项目的允许和拒绝规则，只有获准项目产生文件。活跃会话及服务重启后的会话均拒绝携带其他工作区恢复。 |
| 审批中断线 | OpenAI、Anthropic 分别在审批时断线。两个客户端同时挂回原会话，收到同一请求 ID，同时批准产生一次有效决议、一次重复决议反馈和一条工具结果。 |
| 离线完成与重连边界 | 无客户端时任务继续写文件并完成。另一个用例暂停快照发送，让任务在恢复期间完成，拼接快照和实时事件后，序号、内容与磁盘日志逐条一致。单个客户端发送失败时，另一客户端仍能完成审批和回合。 |
| 同会话互斥 | 空闲释放后同时恢复，只构造一个新 Agent。两个客户端竞争启动回合，只有一个成功，另一个收到 `busy`。此时仍可重连、审批或显式停止。 |
| 期限和释放 | 运行中、待审批的无连接会话均保留。无连接空闲超时后释放模型客户端。审批超时、显式停止和关闭服务都会终结未决审批，后来的决议收到 `expired`。模拟慢资源释放时，关闭操作在设定期限内返回并保留清理任务。 |
| 恢复与兼容 | 服务重启后恢复工作区、消息、工具结果和终态。模拟磁盘上仍为运行中的日志，恢复为失败并使旧审批过期。缺少路径的旧快照必须提供可由原哈希验证的工作区，旧消息在事件流中提供一次历史基线。 |

## 真实浏览器与 MCP

使用同一服务进程运行三个真实 Chromium 标签页，经 Web 审批启动各自的 Playwright MCP。分别让目标标签页空闲关闭、通过 CDP 使目标标签页崩溃，再用另一个连接携带原会话 ID 挂回。两个场景均恢复 `waiting_for_approval` 和一项原审批。显式停止后，分别跟踪的 12 个进程全部退出。第三个会话在两次清理期间保留原进程，获准读取页面后返回 `SESSION-PROBE`，其 12 个被跟踪进程随后全部退出。

复现入口为 `PYTHONPATH=. python -s -B tests/fixtures/web_session_lifecycle.py /tmp/researchagent-session-processes.json`。运行环境使用 Node.js 26.13.1、缓存中的 Playwright 与 Chromium；NSS、NSPR 和 ALSA 动态库临时解包后通过 `LD_LIBRARY_PATH` 提供。页面和 MCP 测试内容均来自本机。
