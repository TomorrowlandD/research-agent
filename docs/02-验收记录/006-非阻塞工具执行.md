# 006 后端基础设施改造 · Commit 2 非阻塞工具执行

2026-11-27，在 WSL Ubuntu 的 `researchAgent` 环境（Python 3.11.18）验证。两个模型协议均使用本地模拟响应，Shell、Linux grep 和 WebSocket 使用实际运行时。

| 场景 | 验收结果 |
| --- | --- |
| 两个 Web 会话同时执行 | 会话 A 的 Shell 写入启动标记并等待释放。释放前，会话 B 完成批准写入和拒绝写入两个回合，均收到流式输出。释放后 A 返回预期输出。 |
| 超时与取消 | 带后代进程的 Shell 分别触发超时、Agent 主动停止和外部任务取消。后代收到 SIGTERM 后继续运行，随后被 SIGKILL 清理。测试核对进程组消失、直接子进程已回收。 |
| 启动与关闭竞态 | 在 asyncio 返回进程句柄前取消，并在清理期间再次取消，进程仍被回收。Shell 正常退出并留下继承输出句柄的后代时也会清理进程组。通过实际 Web 服务关闭入口验证了活动 Shell 的清理。 |
| 双协议历史 | OpenAI、Anthropic 各验证三种中断方式。取消批次保留先前已完成的结果，并为其余调用补齐回执。超时记录工具错误，后续调用继续执行。落盘快照与事件日志的调用 ID、结果顺序和内容一致，恢复后能继续对话。等待审批时取消也能补齐回执。 |
| 输出与搜索 | Shell 的工作目录、空输出、非零退出时的 stdout/stderr、超时提示和长输出截断通过测试。Linux grep 保留匹配行、无匹配和条数上限，超时后直接返回错误。取消阻塞中的 grep 能回收进程。Windows 分支的 Python 搜索回退在 WSL 模拟测试中通过。 |

为避免 Shell 的普通后代继承管道后拖住回收，运行时用临时文件接收 stdout 和 stderr，回收进程后读取结果。Linux/WSL 的清理范围为工具创建的进程组，主动脱离进程组的后代不在范围内。文件读取、目录扫描和 Python 搜索回退在线程中执行；取消等待无法强制中止已经开始的线程读取。
