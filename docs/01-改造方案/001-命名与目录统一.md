# ResearchAgent 命名与 .research 目录改造方案

2026-11-21 · 命名与路径改造已完成，Linux 离线验证通过

开发与验收以 WSL Ubuntu / Linux 为准。对外名称统一为 `ResearchAgent`，用户级配置和数据放入 `~/.research/`，项目级配置和数据放入项目根目录的 `.research/`。运行时从空目录起步，按需创建文件。原 Windows 环境退出维护，历史文件和目录不作为交付内容；旧数据无需复制、备份、迁移或兼容读取。

## 路径与配置

| 用途 | Linux 目标位置 |
| --- | --- |
| 用户设置、个人 Skills、自定义 Agent、计划 | `~/.research/settings.json`、`~/.research/skills/`、`~/.research/agents/`、`~/.research/plans/` |
| 完整会话与超长工具输出 | `~/.research/sessions/`、`~/.research/tool-results/` |
| 按项目区分的长期记忆 | `~/.research/projects/<hash>/memory/`，沿用现有项目哈希算法 |
| 项目设置、Skills、规则与自定义 Agent | 项目根目录的 `.research/settings.json`、`.research/skills/`、`.research/rules/`、`.research/agents/` |
| 项目折叠记录与 Skill 演化记录 | 项目根目录的 `.research/sessions/`、`.research/skill-evolution/` |

完整会话用于 `--resume`，项目内的会话目录用于折叠记录。权限、MCP、Skills 和 Memory 共用路径约定，项目路径按当前工作目录解析。[会话存储](../../agents/session.py) · [长期记忆](../../agents/memory.py) · [权限设置](../../agents/tools.py) · [MCP 设置](../../agents/mcp_client.py)

Linux 下的 10 个业务环境变量从 `BEAR_` 一次性切换为 `RESEARCH_`，保留各自后缀、默认值和命令行优先级。运行时只读取新业务变量，示例和测试同步更新。服务商变量如 `OPENAI_API_KEY` 继续使用原名。[DeepSeek 配置](../../agents/deepseek.py) · [Skills 清理策略](../../agents/skill_evolution.py)

## Git 收录范围

实施时在仓库根目录的 `.gitignore` 添加目录规则 `.research/`。它覆盖仓库内所有同名目录及其内容，包括手写规则、Skills、自定义 Agent、设置、会话和审计产物，暂不设例外。新克隆的项目应能在缺少这些本地文件时启动。用户主目录下的 `~/.research/` 位于本仓库之外。

## 实施与验收

1. 将活跃源码、主模型身份、CLI 帮助和当前配置示例统一为新名称。历史 README 备份和已有验收记录保留原文。
2. 在干净的临时用户目录和项目目录运行 WSL 的 `researchAgent` 环境。保存一条新会话，重启后用 `--resume` 恢复。确认项目折叠记录及长期记忆写到各自的新路径。
3. 创建测试用的本地规则、Skill 和子 Agent，验证发现流程。验证权限与 MCP 都能读取新的设置路径，MCP 同名服务的配置优先级仍为项目根目录 `.mcp.json` 高于项目设置，项目设置高于用户设置。
4. 验证 Linux 下的 `RESEARCH_` 变量生效，单独设置旧业务变量时程序采用默认行为。用 `git check-ignore -v` 抽查 `.research/settings.json`、`.research/skills/demo/SKILL.md` 和 `.research/sessions/demo.json` 均命中整目录规则，然后运行现有 Linux 离线测试。
5. 后续单独改造仓库根目录 `.mcp.json` 中的 Windows 启动命令，在 WSL 与 Linux 容器验证外部服务启动、工具发现和进程回收。

实施结果见[001 验收记录](../02-验收记录/001-命名与目录统一.md)。
